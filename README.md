# Plexus Lab :: Cortex

Оркестратор многоагентной ИИ-компании. **Cortex** — центральный нервный узел:
слушает корпоративную группу в Telegram, маршрутизирует задачи на сабагентов
Google Antigravity (`agy`) и исполняет их действия на сервере.

- **Компания:** Plexus Lab — многопрофильный R&D-центр
- **CEO:** Abdulloh Abbosov — единственное лицо, принимающее решения
- **Сотрудники:** Telegram-боты, за каждым стоит CLI-сессия `agy`
- **Особая роль:** Synapse (COO) — разведка инноваций, единственный с выходом наружу

---

## Быстрый старт

```powershell
cd C:\Projects\PlexusLab
.\deploy.ps1              # создаст venv, поставит зависимости, создаст .env
```

Дальше заполни `.env`:

| Переменная | Где взять |
|---|---|
| `CORTEX_BOT_TOKEN` | @BotFather → `/newbot` → бот-шлюз «Cortex» |
| `CEO_TELEGRAM_ID` | напиши @userinfobot |
| `CORP_GROUP_ID` | запусти Cortex, отправь `/id` в рабочей группе |

**Обязательный шаг:** выключи боту-шлюзу privacy mode, иначе он не увидит
сообщения в группе:
@BotFather → `/mybots` → Cortex → *Bot Settings* → *Group Privacy* → **Turn off**.
Затем добавь бота в рабочую группу.

Запуск:

```powershell
.\deploy.ps1 -Doctor      # предполётная проверка — начни с неё
.\deploy.ps1              # боевой режим (нужен agy в PATH)
.\deploy.ps1 -Mock        # без agy: заглушка отвечает и демонстрирует Tool Use
.\deploy.ps1 -Test        # тесты
```

`-Doctor` ловит то, что иначе проявится молчанием в чате: включённый privacy
mode, бота нет в группе, недействительный токен сотрудника, потерянная
должностная инструкция, ненайденный `agy`. Ничего не меняет и не пишет в чат.

## Antigravity CLI (`agy`)

`agy` — это **отдельный бинарник**, не путать с Antigravity IDE: у IDE
headless-режима нет, она только открывает окно.

```powershell
irm https://antigravity.google/cli/install.ps1 | iex
```

Ставится в `%LOCALAPPDATA%\agy\bin\agy.exe` (без прав администратора, с проверкой
SHA-512), сам прописывается в PATH. **После установки перезапусти терминал.**

Затем — однократный вход в Google:

```powershell
agy -p "ok"
```

Открой выданную ссылку и подтверди доступ. Без входа `agy` отвечает
`Authentication required`, и Cortex покажет это отчётом в чат.

### Как Cortex его вызывает

Синтаксис CLI не зашит в код — он в `config.yaml`:

```yaml
agent_runner:
  driver: "agy"
  drivers:
    agy:
      command: 'agy -p "{prompt}" --output-format text --add-dir "{workspace}" --print-timeout 14m'
```

| Плейсхолдер | Что подставляется |
|---|---|
| `{prompt}` | текст промпта отдельным аргументом — кавычки и переводы строк внутри безопасны |
| `{prompt_file}` | путь к временному `.md` с тем же текстом |
| `{workspace}` | абсолютный путь к папке проекта |
| `{root}` | корень PlexusLab — нужен для своих скриптов, т.к. cwd процесса это папка проекта |
| `{agent}` `{project}` `{model}` | тег сотрудника, имя проекта, `$AGY_MODEL` |

Ответ читается из stdout, ошибки — из stderr. Если CLI умеет принимать промпт
из stdin, поставь `prompt_via_stdin: true` и убери `{prompt}` из команды —
это снимает лимит Windows в 32 767 символов на командную строку.

**Если агенты не смогут читать файлы проекта** (в print-режиме `agy` не у кого
спросить разрешение) — добавь в конец команды `--sandbox` либо
`--dangerously-skip-permissions`. Второй флаг даёт агенту полную свободу
**внутри** проекта; песочницу путей Cortex он не отменяет.

## Как это работает

```
CEO в группе:  @Frontend_Dev почини хедер #basehub_web
        │
        ▼
   Cortex (бот-шлюз, privacy off)
        │  ① охрана: отправитель — CEO или бот из реестра?
        │  ② маршрут: кто вызван, какой проект
        │  ③ контекст: должностная инструкция + история чата + дерево файлов
        ▼
   agy  (cwd = projects/basehub_web, только этот проект)
        │
        ▼
   разбор ответа: текст → в чат, <action>{…}</action> → инструменты
        │
        ▼
   ответ уходит в группу ТОКЕНОМ @Frontend_Dev, а не Cortex
```

---

## Как говорить с Cortex

Никаких команд — пиши свободным текстом в личку боту или в рабочую группу.
Cortex понимает намерение и сам решает, какой инструмент вызвать:

- «кто у нас в штате?» → читает реестр и отвечает
- «найми фронтендера, тег Frontend_Dev» → ведёт через @BotFather словами,
  ждёт токен, нанимает
- «заведи проект sports_api» → создаёт рабочую среду
- «@Frontend_Dev почини хедер» → как и раньше, уходит прямо на `agy`,
  минуя мозг — это адресация конкретному сотруднику, не команда Cortex

Рискованные действия (увольнение, `execute_command`, архивирование,
отключение проекта) Cortex подтверждает кнопками «✅ Выполнить / ❌ Отмена»,
если не задано иное в `config.yaml -> brain.autonomy`.

---

## Найм

Найм — разговор, не мастер из шагов. Напиши Cortex в личке (токен не
должен попасть в общий чат): скажи, кого хочешь нанять и на какую роль.
Cortex попросит тебя создать бота в @BotFather (`/newbot`, выключить Group
Privacy, добавить в рабочую группу) и пришлёт токен — вставь его в чат.
Дальше Cortex сам проверит токен, сгенерирует должностную инструкцию и
включит сотрудника без перезапуска сервера.

## Изоляция проектов

Каждый проект — папка в `projects/`. Существующий код **никуда не переезжает**:
`/project link` создаёт directory junction, файлы остаются там, где лежали.

```
projects/basehub  ──junction──►  C:\Projects\Basehub
```

`/project unlink` снимает только саму ссылку (`os.rmdir`, не `rmtree`) — целевая
папка не страдает. Архивирование подключённого проекта запрещено: оно утащило бы
чужой репозиторий.

Агент получает `cwd` ровно своего проекта и физически не видит чужой код. Любой путь из ответа агента проходит через
`resolve_path()`: `../basehub_web/.env` из проекта `sports_api` будет отклонён
**до** исполнения.

Задачи внутри одного проекта выполняются строго по очереди — два агента не
правят один репозиторий одновременно. Разные проекты идут параллельно
(`concurrency.max_parallel_tasks`).

## Tool Use

Агент влияет на мир, вставляя в ответ блок:

```
<action>
{"tool": "execute_command", "args": {"command": "git status"}}
</action>
```

Текст **вне** блоков уходит в чат как реплика сотрудника. Блоков может быть
несколько — выполняются по порядку, до первой неудачи.

| Инструмент | Что делает |
|---|---|
| `execute_command` | консоль внутри папки проекта: git, npm, python, yt-dlp… |
| `send_file` | отправить файл из проекта в чат |
| `update_telegram_profile` | бот правит себе имя, био и краткое описание |
| `update_system_prompt` | рекурсивное самоулучшение: переписать свою инструкцию |
| `web_research` | HackerNews и чтение веб-страниц — **только у Synapse** |

Кому что доступно — в `config.yaml → tools` (или персонально, полем `tools`
в реестре). Парсер терпит неаккуратность моделей: ```` ```json ````-обёртки,
трейлинг-запятые, синонимы ключей (`action`/`params`), плоские аргументы.
Сломанный блок не отменяет остальные.

## Synapse — COO / Директор по инновациям

Единственный сотрудник с доступом наружу и **без** `execute_command`: он не
пишет код. Его работа — приносить CEO сжатые сводки того, что происходит в
индустрии, и переводить их в предложения фич.

```
/digest              топ HackerNews выше порога значимости
/digest rust wasm    поиск по конкретной теме
```

Сводка приходит в личку CEO от лица самого Synapse
(`synapse.digest_target: ceo_dm | group`).

## Безопасность

- Cortex реагирует **только** на CEO и на ботов из `employees_registry.json`.
  Все остальные игнорируются молча — ответ незнакомцу подтверждает, что
  система жива.
- Разрешены только чат CEO и `CORP_GROUP_ID`. Даже CEO из постороннего чата
  не будет услышан.
- `execute_command` проверяется по blocklist регексов (`rm -rf /`, `format C:`,
  `shutdown`, `git push --force`…) — список в `config.yaml`.
- Выход за пределы папки проекта заблокирован.
- Падение `agy` не роняет Cortex: `stderr` перехватывается и уходит в чат
  аккуратным отчётом с кодом возврата, временем и хвостом лога.
- `employees_registry.json` содержит боевые токены и **не коммитится**.
  При каждой записи создаётся `.bak`.

## Что делать, если

**Cortex молчит в группе.** Не выключен privacy mode у бота-шлюза, либо в `.env`
не тот `CORP_GROUP_ID`. Отправь `/id` в группе и сверь.

**«Исполняемый файл 'agy' не найден».** `agy` не в PATH или другой синтаксис —
поправь `agent_runner.drivers.agy.command` в `config.yaml`.

**Бот отвечает, но задачи не берёт.** Не создан ни один проект: `/project new …`.
Или проектов несколько и не выбран активный: `/use sports_api`.

**Хочу проверить систему без agy.** `.\deploy.ps1 -Mock` — заглушка отвечает
осмысленно и присылает настоящий блок `<action>`, чтобы проверить Tool Use.

Подробности архитектуры — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
