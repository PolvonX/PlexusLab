# Cortex Brain — Claude как «мозг» оркестратора

Дата: 2026-08-13
Статус: утверждён CEO, готов к планированию реализации

## Зачем

Сейчас Cortex — детерминированный `aiogram`-бот: понимает только точные
команды (`/hire`, `/staff`, `/fire`…) и тег `@Кого_то задача`. Никакого ИИ в
самом Cortex нет — вся логика это Python-код и конечный автомат состояний
(`telegram/hiring.py`).

Цель этой доработки: Cortex сам становится ИИ-агентом на Claude — понимает
свободную речь CEO, сам решает, что делать (нанять, уволить, создать проект,
поставить задачу сотруднику), и может «учить» новых сотрудников — писать или
дополнять их должностные инструкции, либо делегировать обучение агенту на
`agy`. Рутинная инженерная работа (`@Tag задача`) по-прежнему уходит на `agy`
напрямую — Claude на неё не тратится. Claude тратится только на разговор с
CEO и управленческие решения.

Доступ — через локальный CLI `claude` (Claude Code) субпроцессом, той же
схемой, что и `agy` для сотрудников: расходуется существующая подписка
Claude Code, отдельный `ANTHROPIC_API_KEY` не нужен.

## Архитектура

### Новый драйвер `claude`

Третий драйвер в `agent_runner.drivers` (`config.yaml`), рядом с `agy` и
`mock`. `runtime/runner.py` не меняется — он уже общий, не завязан на
конкретный CLI (запуск подпроцесса, таймауты, перехват `stderr`, отчёт об
ошибке в чат).

```yaml
claude:
  command: >
    claude -p "{prompt}" --output-format text
    --system-prompt "{system_prompt}" --tools ""
    --model sonnet --session-id {session}
  prompt_via_stdin: false
```

- `--tools ""` — отключает встроенные Bash/Edit/Read. Мозг не трогает файлы
  и консоль напрямую, только через наш текстовый контракт `<action>`. Вся
  песочница путей и `command_blocklist` остаются в силе.
- `--system-prompt` передаётся как отдельный аргумент процесса (та же схема,
  что и `{prompt}` — кавычки и переводы строк безопасны, лимит Windows на
  длину командной строки не в счёт, пока промпт не приближается к 32k
  символов; если разрастётся — переносим в `{prompt_file}`, плейсхолдер уже
  поддержан).
- Авторизация — обычная OAuth-сессия Claude Code на машине (не `--bare`, не
  `ANTHROPIC_API_KEY`).

### Сессии на чат — экономия токенов

`{session}` = детерминированный `uuid5(chat_id)`. Первый вызов для чата —
`--session-id <uuid>`, дальше `--resume <uuid>`: не пересылаем весь контекст
(штат, проекты, историю) заново на каждой реплике, только новую.

Если резюме не удалось (сессия потеряна, процесс на другой машине, чистка
диска) — фолбэк на полную пересборку контекста из `data/history/`, который
уже пишется для всех чатов. Это не новый механизм хранения, а уже
существующий лог, использованный как источник восстановления.

**Открытый вопрос для реализации:** ведёт ли `claude --resume <uuid>` себя
предсказуемо, если сессии с таким id ещё не существует (создаёт новую или
падает) — проверяется на этапе реализации, до дизайна не блокирует.

### Модуль `cortex/brain/`

Новый пакет, аналог `cortex/agents/synapse.py` по роли, но по объёму больше:

```
cortex/brain/
├── agent.py       цикл «контекст → claude → parser → инструменты → …»
├── context.py     сборка системного промпта + состояния компании
├── session.py     uuid5(chat_id) → --session-id/--resume, фолбэк на историю
│                  при неудаче резюме (никакого отдельного стора: id всегда
│                  выводится из chat_id, хранить нечего)
├── confirm.py     риск-политика, pending actions
└── tools/         мета-инструменты (см. ниже), тот же контракт ToolResult
```

Ответ мозга разбирается тем же `tools/parser.py`, что уже читает `<action>`
у сотрудников — парсер общий, не завязан на то, кто его вызвал. Для мозга
регистрируется свой `ToolRegistry` с другим набором инструментов.

### Поток сообщения

```
сообщение от CEO → SecurityMiddleware (без изменений)
       │
       ├─ есть @Tag зарегистрированного сотрудника?
       │      да → напрямую в существующий orchestrator.dispatch (agy),
       │           Claude не вызывается — как сейчас
       └─ нет
              ↓
        brain.agent: context.py собирает промпт → claude -p → parser
              ↓
        риск действия выше порога autonomy? → confirm.py: кнопки, ждём
        иначе → выполнить инструмент, результат → снова в мозг
              ↓
        цикл до brain.max_iterations (5) → затем текст в чат от лица Cortex
```

`@Tag` остаётся прямым маршрутом мимо Claude: это обращение к конкретному
человеку/сотруднику, а не команда самому Cortex. Так инженерная нагрузка
остаётся на `agy`, Claude — только на разговор и управление.

Цикл (не одна пара запрос-ответ) нужен, потому что часть ответов CEO требует
сначала прочитать состояние (`list_staff`), и только потом ответить осмысленно.

## Мета-инструменты и риск

| Инструмент | Риск | Реализация переезжает из |
|---|---|---|
| `list_staff`, `get_employee`, `list_projects`, `get_status` | safe | `handlers.py` (чтение) |
| `hire_employee(name, role, token)` | normal | `hr.py` (без изменений по сути) |
| `write_job_description(name, mode, text)` | normal | новое — «учить сотрудника»; `mode` = `append`/`replace`, та же семантика, что уже есть у `update_system_prompt` |
| `create_project`, `link_project`, `set_chat_project`, `set_listen` | normal | `handlers.py` / `workspace/manager.py` |
| `assign_task(employee, project, task)` | normal | `orchestrator.dispatch` (переиспользуется как есть) |
| `send_file`, `request_digest` | normal | `tools/send_file.py`, `agents/synapse.py` |
| `fire_employee`, `archive_project`, `unlink_project`, `execute_command` | risky | `hr.py` / `workspace/manager.py` / `tools/execute_command.py` |

`write_job_description` закрывает «научить сотрудника»: мозг либо сам
дописывает `.md`-инструкцию (`update_system_prompt`-механизм уже есть и
переиспользуется), либо решает делегировать обучение через `assign_task` —
тогда ТЗ на обучение пишет уже нанятый агент на `agy`, чужими токенами.

Найм становится разговором, а не мастером из трёх шагов: Claude ведёт CEO
через BotFather словами (шаг с созданием бота в BotFather убрать нельзя —
Telegram не даёт ботам создавать ботов), и вызывает `hire_employee` одним
действием, когда в истории чата уже есть тег, должность и токен. Явного FSM
для этого не нужно — память о том, что «мы посреди найма», это сама история
чата в сессии Claude.

## Подтверждение рискованных действий

Порог — не бинарный переключатель, а настройка:

```yaml
brain:
  autonomy: balanced        # cautious | balanced | autonomous
  max_iterations: 5         # предохранитель цикла «инструмент → снова в мозг»
  risk_overrides:           # точечно переопределить риск инструмента
    execute_command: risky
```

| Режим | safe | normal | risky |
|---|---|---|---|
| `cautious` | сразу | подтвердить | подтвердить |
| `balanced` (по умолчанию) | сразу | сразу | подтвердить |
| `autonomous` | сразу | сразу | сразу |

Подтверждение — inline-кнопки «✅ Выполнить / ❌ Отмена» в Telegram, не разбор
слова «да» из текста (свободная фраза неоднозначна: «ну давай наверное» —
это согласие или сомнение). Отложенное действие сохраняется в
`data/pending_actions.json` (та же схема атомарной записи, что у
`employees_registry.json`) и переживает перезапуск процесса.

## Обработка ошибок

Никакого запасного командного интерфейса. Если `claude` падает или не
авторизован — тот же путь, что сейчас у `agy`: `AgentRunError` со `stderr`,
кодом возврата и временем уходит в чат аккуратным отчётом
(`formatting.error_report`, без изменений). Cortex ничего не «понимает» без
Claude — и это осознанный выбор CEO, не пробел.

## Что удаляется, что остаётся

**Удаляется как UX:** `telegram/handlers.py` (13 команд-обработчиков),
`telegram/hiring.py` (FSM найма), `telegram/routing.py` в части разбора
`@Tag #project текст` для команд самому Cortex (разбор `@Tag` для адресации
сотруднику — остаётся, это не команда Cortex).

**Логика не выбрасывается**, переезжает в `brain/tools/` как реализация
мета-инструментов: код `hr.py`, `registry.py`, `workspace/manager.py`,
`orchestrator.py` используется как есть, просто вызывается из нового места.

**Без изменений:** `runtime/` (весь пакет), `tools/parser.py`,
`tools/base.py`, `security.py`, `middleware.py`, `bot_pool.py`,
`formatting.py`, работа сотрудников через `agy`, Synapse.

## Вне рамок этой итерации

- Автономное построение команды с нуля («построй мне команду для X») — явно
  отложено самим CEO на следующий шаг, после того как этот слой обкатается.
- Оптимизация системного промпта под prompt-cache
  (`--exclude-dynamic-system-prompt-sections`) — не нужно, пока не видно
  проблем со стоимостью.
- Строгий `--json-schema` для ответов мозга — используется тот же
  текстовый `<action>`-контракт, что и у сотрудников, ради единообразия
  и переиспользования парсера.

## Тестирование

- Мок-драйвер для `claude`, аналогичный `scripts/mock_agy.py` — детерминированный
  ответ с `<action>` для тестов без живого CLI и без трат подписки.
- Юнит-тесты мета-инструментов по образцу существующих
  (`tests/test_parser.py`, `tests/test_orchestrator.py`, `tests/test_registry.py`) —
  тот же стиль, что уже даёт 70 прошедших тестов.
- Тест на риск-политику: `cautious`/`balanced`/`autonomous` и
  `risk_overrides` дают правильное решение «выполнить сразу / спросить».
- Живой прогон (ручной, не автоматизированный): естественная фраза в
  Telegram → `hire_employee` → сотрудник в штате, без единой команды.
